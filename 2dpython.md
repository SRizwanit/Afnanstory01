## 0. HOW TO USE THIS FILE (Protocol)

### 0.1 Rules for the AI (strict)
1. **One step = one file.** Each step creates or fully rewrites exactly ONE file (listed in the step). Never touch other files in the same step. If a bug is found in an older file, that fix becomes its own new step (e.g. `Step 12b`).
2. **No sub-folders at all**, except `.github/workflows/render.yml` (GitHub requires this path). Everything else lives in the repo root (flat).
3. **Do not re-read old files** to continue. Use the *Interface Contracts* (Section 6) in this file. Only open an old file if a contract is unclear.
4. **After finishing every step the AI must deliver exactly two things:**
   - `2dpython_project_vNN.zip` — the **full updated project** (all files so far; flat; plus `.github/workflows/render.yml`).
   - `2dpython.md` — this file, updated: the finished step ticked ✅, the *Progress Log* (Section 9) row filled in with details (what was built, exports, notes, how to test).
5. After delivering, the AI replies in Bengali with a **short** summary: what was done, what the next step is, and any action the user must take. No long recaps.
6. Keep every file **small and focused** (target: under ~250 lines per file). If a file would exceed ~350 lines, split it into two steps/files.
7. The AI works in **English in code & comments**, talks to the user in **Bengali**.
8. Never invent story facts. Story facts come only from `horror1.json` (and future part files). Unknown facts (e.g. wife's name, Prokash's age) stay generic or are marked `TODO(user)`.
9. Determinism: **no `Math.random()`, no CSS animations/transitions, no `setTimeout`.** Use `useCurrentFrame()`, `interpolate()`, `spring()`, and Remotion's `random(seed)`. Otherwise frames render differently across parallel workers.
10. Test what you can locally (e.g. run `python3 build_data.py`, `node --check` on `.js`), and state honestly in the log what was **not** testable (JSX render needs the GitHub Action).
12. **No-overlap rule (user requirement, Step 4):** captions, name tags, location labels, age counters, titles, characters and any other key element must never overlap each other. Every visual file takes its geometry ONLY from `useLayout()` (`caption` band / `content` zone / `LAYERS`, Section 6.1). Scenes place key elements inside the content zone via `L.cx(pct)` / `L.cy(pct)`; only `Captions.jsx` draws inside the caption band; text-bearing elements that appear at the same time must be given different slots (e.g. top row vs bottom row) — never the same coordinates.
11. Bengali text rule: animate **per word only** (or per grapheme cluster via `Intl.Segmenter`). **Never split Bengali words into single Unicode characters** — it breaks conjuncts (যুক্তাক্ষর) such as ্র, ্ম, ঙ্ক.

### 2.2 ⚠️ Mismatch to handle
The JSON ends at **18.91 s** but the WAV is only **18.00 s** (0.91 s difference).
Possible causes: (a) JSON timings are estimated, not forced-aligned; (b) audio is slightly cut at the end; (c) different playback speed.
Strategy implemented in `build_data.py` (Step 5), env var `SYNC_MODE`:
- `keep` *(default)*: use JSON times as-is; timeline length = `max(audio, lastWordEnd) + tail`. Last 0.91 s of captions play over silence/ambience.
- `fit`: linearly scale all word times by `audioDuration / lastWordEnd` (≈ 0.952).
- `offset:<sec>`: shift all words by a constant (e.g. `offset:-0.2`).
The GitHub Action exposes `sync_mode` as an input so the user can preview a still/draft with each mode and pick the best, **no code change needed**. Later parts should ideally come with accurate alignment (e.g. from the TTS tool).

**✅ RESOLVED in Step 2b (2.2b):** The WAV is **not** cut. Silence/energy analysis shows the speech really ends at **≈17.80 s** (audio file is 18.00 s, 0.2 s of trailing silence); the original JSON was only an estimate that ran too long (18.91 s). `horror1.json` has been re-timed accordingly (see 2.3b). Consequences: `SYNC_MODE=keep` (default) is correct; `fit` would only scale by ≈1.01 (pointless); `offset:` not needed. Timeline length = audio 18.00 s + tail.
**Method used (reuse for `horror2`, …):** (1) RMS envelope of the mono WAV in 10 ms windows; (2) silence gaps = frames below **peak − 35 dB (−44 dBFS)** lasting ≥ 50 ms; (3) dynamic-programming alignment of the 34 words to the speech so that every punctuation mark (`।` `,`) lands on a real silence gap, long gaps (≥ 0.25 s) only sit after punctuated words, and word durations stay proportional to their Bengali syllable (akshara) count; (4) word `end` = start of the silence gap, next `start` = end of the gap. Result: all 7 punctuation pauses matched real gaps (2.21→2.86, 7.19→7.61, 9.50→9.74, 10.37→10.74, 12.22→12.39, 13.76→14.15, 15.77→16.16). Time precision ≈ ±0.03 s at pauses, ±0.1 s for boundaries inside a continuous run of words (no audible silence there, so proportional + energy-dip estimate). If a caption ever feels early/late, use `sync_mode=offset:±0.1` in the Action.

### 3.5 Design rules (apply to every visual file)
1. **Resolution-independent layout:** never hardcode pixels. Use `useLayout()` from `theme.js` → `u(n)` returns `n × (min(width,height)/1000)`; positions as percentages of width/height. The same scene must look right in 9:16 **and** 16:9 (re-arrange: vertical = stacked layout, horizontal = side-by-side layout, via `layout.isVertical`).
2. **Safe zones:** vertical videos keep important content out of top 10% and bottom 22% (UI overlays on Reels/Shorts). Captions sit at ~64–72% height in vertical, ~80% in horizontal.
3. **Colorful but horror:** dark teal/indigo base, with saturated accents: blood red `#ff2d3d`, amber `#ffb020`, toxic green `#7cff4f`, ghost cyan `#4fe3ff`, violet `#b46bff`, bone `#f3ecdc`. Keep backgrounds dark so captions pop.
4. **All motion** via `interpolate`/`spring` with `extrapolateRight:'clamp'`.
5. **Randomness** only via `random('seed-string')` from `remotion`.
6. SVG over images. No external image/video downloads. Fonts only via `@remotion/google-fonts` (the Action has internet).
7. Each component is **pure** and takes `frame`-independent props; it reads the clock itself with `useCurrentFrame()`.
8. Performance: avoid huge blur filters on full-screen elements every frame; prefer pre-baked gradients; limit particles to ≤ 60; no more than ~3 full-screen SVG filters at once.
9. File header comment in every file: purpose, exports, props.
10. **Zones (no overlap):** `useLayout()` reserves a **caption band** (vertical: ≈59–76 % of height; horizontal: ≈69–93 %) and a **content zone** above it (`content.bottom = caption.top − 28 px·unit`). Key art/text lives in the content zone; full-bleed backgrounds, fog, grain and vignette may cover everything but carry no text. Ground/foreground decoration under the caption band must stay low-contrast so captions stay legible.
11. **Layers (z-index) from `LAYERS`:** bg 0 · scene 10 · fx 20 · captions 30 · film 40 · transition 50 · hud 90. Captions are always above scenes+fx and below film grain.
12. Elements that appear together inside a scene (e.g. 3 location labels, 5 character name tags, 2 age counters) get **separate slots** computed from the content zone (rows/columns), and are checked mentally at both 1080×1920 and 1920×1080 before finishing the file.

## 4. MOBILE WORKFLOW DETAILS (what `render.yml` must do — Step 9 / Step 36)

**Triggers:** `workflow_dispatch` only (manual).
**Inputs:**
- `part` (string, default `horror1`) → picks `<part>.wav/.json`
- `orientation`: `vertical | horizontal | both` (default both)
- `quality`: `hd | 4k | both` (default hd)
- `mode`: `video | draft | still | thumbnail` *(thumbnail added in Step 37)*
- `still_frames`: comma list, default `30,120,300,450,560`
- `sync_mode`: `keep | fit | offset:-0.2` (default keep)
- `intro`: `true|false`, `outro`: `true|false`
- `thumb_title`: string (thumbnail mode; blank = default title, max 80 chars) · `thumb_subtitle`: string (optional) *(Step 37)*
- `publish_release`: `true|false`

**Job steps:**
1. `actions/checkout@v4` (with `permissions: contents: write`)
2. **Unpack**: if `update.zip` exists → `unzip -o update.zip -x ".github/*"` → `rm update.zip` → `git add -A` → commit as `github-actions[bot]` → `git push`. (`.github/*` is excluded because `GITHUB_TOKEN` is not allowed to modify workflow files.)
3. `actions/setup-node@v4` (Node 20, npm cache) + `actions/setup-python@v5` (3.11)
4. `python build_data.py --part $PART --sync $SYNC` then `python make_ambience.py --part $PART`
5. Install Linux libs required by Chrome Headless (libnss3, libdbus-1-3, libatk1.0-0, libasound2t64 / libasound2, libxrandr2, libxkbcommon0, libxfixes3, libxcomposite1, libxdamage1, libgbm1, libcups2, libpango-1.0-0, libcairo2) — verify against current Remotion docs.
6. `npm install` (or `npm ci` once a lockfile exists) → `npx remotion browser ensure`
7. Render matrix via `strategy.matrix` (or sequential shell loop): `npx remotion render index.js <Composition> out/<label>.mp4 --scale=<s> --crf=<n> --codec=h264 --pixel-format=yuv420p --concurrency=2 --props='{"part":"..."}'`
   > `out/` is created in the runner only (it is **not** committed, and nothing in the repo uses sub-folders).
8. `actions/upload-artifact@v4` (retention 14 days) for each MP4/PNG.
9. Optional: `softprops/action-gh-release@v2` attaching MP4s (limit 2 GB/file).
10. **(Step 37)** Retries: `apt-get`, `npm install`, `npx remotion browser ensure` and every render/still command run up to 3 times (waits grow: 10–20 s, 15–60 s); partial output is deleted before a retry. Preflight in `prepare` checks required files; a final `summary` job writes a table (OK/MISSING per output, sizes, release link) to the run's job summary.

### 6.3 Scene component contract
